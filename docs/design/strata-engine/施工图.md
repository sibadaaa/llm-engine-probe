## 1. T2.1 + T2.2 · 组件 profile（两端，字段一一对应）

### `engines/strata.sh`（全文草稿，可直接落盘后按 ⭐ 核对结果修正）

```bash
# ============================================================================
# 引擎组件 profile：Strata（消费级 PC 的 MoE 专家分层推理引擎）。
# 与 vendors/*.sh 同纪律：只允许变量赋值/函数定义，source 必须无副作用。
# 事实依据：docs/design/strata-engine/事实核对.md；⭐ = 真机核对项。
# ============================================================================
ENGINE_ID=strata
ENGINE_LABEL="Strata（MoE 专家分层推理引擎）"

# host 模式默认入口：无交互起服务。模型/端口/上下文优先经 strata-<model>.json 固化；
# ⭐ strata launch 的 --port 支持待核，未确认前端口经 HOST_SERVE_ENTRYPOINT 覆盖传入。
ENGINE_ENTRYPOINT="strata launch --yes --no-tui"

# 进程清理正则：⭐ 占位（App/Terminal/server.py/engine 二进制的真实进程名待 ps -ef 核对）。
ENGINE_PROCESS_PATTERN="strata|server\.py"

ENGINE_HEALTH_PATH="/health"
ENGINE_MODELS_PATH="/v1/models"
ENGINE_METRICS_FLAVOR="vllm-named"        # /metrics 以 vLLM 指标名输出 Prometheus 文本
ENGINE_ARGS_MODE="custom"                 # 无 vLLM serve 子命令语义：跳过全部 vLLM flag 拼装
ENGINE_READY_METRIC='^vllm:num_requests_(running|waiting)'   # ⭐ 无 cache_config_info，换计数器；真机核对
ENGINE_METRICS_FETCH_SUFFIX="?format=prometheus"             # /metrics 默认 JSON，必须显式要文本
ENGINE_VERSION_CMD="strata --version"                        # ⭐ 未确认；备选 strata doctor / GET /props
ENGINE_CHECK_SEVERITY="warn"              # 常态是外部机器探测，本机没装不拦预检
ENGINE_DOCKER_IMAGE=""                    # 无官方镜像：RUNTIME=docker 显式拒绝
ENGINE_CAPS="api.openai-chat api.models-list api.health api.props spec.decode metrics.vllm-named metrics.prometheus runtime.host"
ENGINE_NOTES="MoE 专家分层(VRAM/内存/NVMe)+MTP 投机；默认单请求串行；无逐 step 日志/torch profiler/图模式；思考计入 max_tokens。"
```

### `probe/engines.py` 注册条目（T2.2，与上面逐字段一致）

```python
"strata": EngineProfile(
    id="strata",
    label="Strata（MoE 专家分层推理引擎）",
    caps=frozenset({
        "api.openai-chat", "api.models-list", "api.health", "api.props",
        "spec.decode", "metrics.vllm-named", "metrics.prometheus", "runtime.host",
    }),
    entrypoint="strata launch --yes --no-tui",
    process_pattern=r"strata|server\.py",
    metrics_flavor="vllm-named",
    args_mode="custom",
    ready_metric=r"^vllm:num_requests_(running|waiting)",
    metrics_fetch_suffix="?format=prometheus",
    version_cmd="strata --version",
    check_severity="warn",
    report_notes=(
        "Strata 为消费级 MoE 专家分层引擎：逐 step / stat-logger / torch profiler / "
        "图模式观测不适用；思考计入 max_tokens（建议 PROBE_MAX_TOKENS≥256）；"
        "默认单请求串行，并发吞吐解释需谨慎。",
    ),
    notes="详见 docs/design/strata-engine/事实核对.md",
),
```

**caps 取舍说明**（对照 `tests/test_engines.py` 词表）：
* 无 `api.openai-completions`（上游无 `/v1/completions`）→ `PROBE_ENDPOINT=completions` 被拒；
* 无 `obs.*` 四项、无 `runtime.docker` → F1 的 caps 门禁自动完成降级/拒绝；
* `spec.decode` 有（MTP `--spec N --mtp`）但 `obs.spec-metrics` 无（`/metrics` 级 draft/accepted
  计数器虽有，**先不声明**——它在 `metrics.vllm-named` 的通用解析里自然出现，
  声明 `obs.spec-metrics` 意味着投机解码**归因小节**可用，而 vLLM 版依赖 per-request 数据，
  等 F3 确认 Strata 计数器可支撑归因后再声明）。

验收：`python3 -m probe engine --engine strata` 打印能力位与 notes；`tests/test_engines.py`
两端一致性全绿。

## 2. T2.3 · 引擎模板与 selftest

### `hosts/engine/strata.env`（全文草稿）

```bash
# 用途：切换引擎到 Strata（消费级 MoE 专家分层推理引擎，host 模式结构适配）。
# 适用：Linux NVIDIA/AMD 机器且已按上游装好 strata 命令；或配合 deploy/external-probe.sh
#       只读探测另一台机器（含 Windows）上已运行的 Strata 服务。
# 组合：hosts/vllm-host.sh up engine/strata                      （单模板即可）
#       hosts/vllm-host.sh up vendor/nvidia engine/strata        （显式指定厂商做遥测）
# ============================================================================
# 说明：
#   * Strata 的模型是 pack 名（q2_0/iq3_s/...）或本地 GGUF 目录，不是 vLLM 权重路径；
#     TP/DTYPE/GPU_MEM_UTIL 等 vLLM 键对 Strata 无意义（custom 模式下不参与拼装）。
#   * 引擎参数用 EXTRA_ENGINE_ARGS 追加（值内不能有空格）；STRATA_* 环境用 EXTRA_ENV：
#     EXTRA_ENGINE_ARGS="--spec 4 --mtp"
#     EXTRA_ENV="STRATA_IQ_MT_MIN=1"
#   * 探测默认打到本机 :8100（PORT）。Strata 默认监听 8080：要么在 strata-<model>.json
#     固化端口，要么用 HOST_SERVE_ENTRYPOINT 显式覆盖入口并传 --port（⭐ flag 支持待核）。
#   * 外部已运行的 Strata（另一台 PC / Windows）：不要 up，直接看
#     docs/strata-接入指南.md 的 external-probe 流程。
#
# 覆盖键：ENGINE、MODEL、SERVED_NAME、HOST_ENGINE_PATTERN、HOST_SERVE_ENTRYPOINT（注释）。
# 风险：
#   1) 首次启动要把专家加载进内存（约 1-3 分钟整机卡顿属正常）；
#   2) 长 prompt 首读约 1 分钟/30K tokens，压测前先跑一次预热（PROBE_TIMEOUT 建议 ≥1800）；
#   3) 思考计入 max_tokens 且默认 high 档：PROBE_MAX_TOKENS 建议 ≥256；
#   4) A/B 对比要可复现时：EXTRA_ENV 加 STRATA_IQ_MT_MIN=1，EXTRA_ENGINE_ARGS 加
#      --prompt-cache 0 --adapt-swaps 0 --pcie-frac 0（decode 会变慢，仅对比实验用）。
# ============================================================================

ENGINE=strata
MODEL=q2_0                     # pack 名（或本地 GGUF 目录）；按机器内存选档（见事实核对 §2）
SERVED_NAME=strata             # Strata 已加载模型的注册名；探针统一用它
# 进程清理正则（⭐ 结构占位，真机 `ps -ef | grep -i strata` 后修正）：
HOST_ENGINE_PATTERN="strata|server\.py"
# 服务化入口按站点覆盖（模型/端口/上下文在此固化）：
# HOST_SERVE_ENTRYPOINT="strata launch --model q2_0 --yes --no-tui --port ${PORT}"
```

## 3. T2.4 · `docs/strata-接入指南.md` 大纲（章节即验收项）

1. **两种探测姿势的选型**：外部只读（Strata 常态：消费级 PC / Windows / 已在跑）vs host 拉起
   （Linux NVIDIA/AMD 机器、`strata` 命令可用）。
2. **外部只读流程**（主推）：Strata 侧 `strata launch --access lan` 拿 API key 与端口 →
   本工具侧 `VLLM_BASE_URL=http://<pc>:8080 VLLM_API_KEY=<key> PROBE_OUTDIR=... python3 -m probe env`
   自检 → `bash deploy/external-probe.sh <strata 的 serve.log 或任意存在文件>` 走
   probe_all 全链路；列出 `PROBE_ENDPOINT=chat`（completions 不可用）、`PROBE_TIMEOUT`、
   `PROBE_MAX_TOKENS` 建议值。
3. **host 拉起流程**：`hosts/vllm-host.sh up engine/strata`；`strata-<model>.json` 固化端口与
   `--parallel` 的做法；`strata launch --plan` 预检；停止用 `hosts/vllm-host.sh down`
   （进程正则 `HOST_ENGINE_PATTERN`）+ `strata launch --stop` 兜底。
4. **指标抓取说明**：`/metrics` 需 `?format=prometheus`（探针已自动带）；vLLM 同名子集 +
   `strata:*` 专有指标的对照表（引事实核对 §6）；Prometheus/Grafana 想直接抓时给
   `Accept: text/plain` 说明。
5. **压测语义差异**：思考计入 max_tokens、默认串行、首读慢、A/B 可复现组合（引事实核对 §7/§8）。
6. **排障**：`strata doctor`、`strata monitor --url`、`/props`、`/status`；常见报错
   （端口占用=已有实例、内存不足降档、draft head 不 fit）。
7. **真机验证清单**：http → suite → report → compare 全链路在 Strata 上的逐项预期
   （哪些小节为空、哪些指标缺失属预期）。

## 5. T2.6 · 探针兼容性回归核对（无硬件即可做大部分）

```bash
# ① 组件与配置流
python3 -m probe engine                    # 列出 vllm + strata
python3 -m probe engine --engine strata    # 能力位/notes 正确
python3 -m unittest tests.test_engines -v  # 两端一致 + caps 词表

# ② dry-run 结构验证（无 GPU/无 strata 也能跑）
RUNTIME=host RUNS_DIR=/tmp/f2-runs hosts/vllm-host.sh dry-run engine/strata
#   serve_launch.sh 预期：无 --tensor-parallel-size 等 vLLM flag（custom 模式）；
#   含 ENGINE=strata 导出、ENGINE_ENTRYPOINT 入口、EXTRA_ENGINE_ARGS 透传、
#   HOST_ENGINE_PATTERN 出现在 stop 用的正则里
RUNTIME=docker RUNS_DIR=/tmp/f2-runs hosts/vllm-host.sh dry-run engine/strata   # 预期 die（docker）
PROBE_ENDPOINT=completions RUNTIME=host RUNS_DIR=/tmp/f2-runs \
  hosts/vllm-host.sh dry-run engine/strata                                        # 预期 die（无该 API）

# ③ hostcheck（ENGINE_CHECK_SEVERITY=warn 路径）
ENGINE=strata python3 -m probe hostcheck --skip-gpu --json    # engine 检查项 warn 不 fail

# ④ 默认路径无回归
python3 -m unittest discover -s tests && bash tests/host_templates_selftest.sh
```

真机追加（有 Strata 机器时）：`probe env` → `probe http`（TTFT/ITL 出数、reasoning delta
被计数）→ `probe metrics`（vllm: 子集 + 缺项 `available=False`）→ `suite` + `compare`
（schema 缺项 null）→ `report`（引擎行 + 能力降级注记）。逐项预期写进接入指南 §7。
