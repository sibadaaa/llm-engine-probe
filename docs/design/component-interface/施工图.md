### T1.7 `start_vllm.sh` 分支收拢（最大改动面，逐块列出）

收拢原则见 [设计.md](设计.md) §7。逐块改法（行号为编写时位置）：

1. **配置读入后**（≈ L63-97 之间，runtime 归一化之后、必填校验之前）调用 `engine_meta` +
   合法性检查：未知 `ENGINE` die；无 `runtime.docker` 且 `RUNTIME=docker` die（文案含
   "该引擎暂无 docker 支持"）；`DRAFT_MODEL/SPEC_METHOD` 非空且无 `spec.decode` die；
   `PROBE_LEVEL∈{steps,deep}` 且无 `obs.step-log` → `warn` + 降级 `basic`；
   `PROBE_LEVEL=kernel` 且无 `obs.trace-pytorch` → `die`（kernel 档依赖 torch profiler，
   降级没有意义；vllm profile 含该能力，基线不变）；`PROBE_PLUGIN=1` 且无 `obs.step-log`
   → `warn` + 置 0；`PROBE_ENDPOINT=completions` 且无 `api.openai-completions` → die。
2. **段1 基础参数**（L99-111）：L99-111 是"vLLM CLI 的 `serve` 子命令形态"，属于 vLLM
   引擎的参数拼装，不宜逐 flag 包 if（30+ 个 flag 会把可读性打碎）。切法：profile 声明
   `ENGINE_ARGS_MODE=vllm-cli`（唯一合法值，其它引擎 = `custom`），L99-237 的**全部**
   vLLM flag 拼装块由该门禁整体收拢；`custom` 模式下仅保留 `EXTRA_ENGINE_ARGS`/
   `EXTRA_ARGS_FILE` 追加与 `MODEL/SERVED_NAME/PORT` 等记录性字段。`ENGINE_ARGS_MODE`
   是新增 profile 字段（设计 §4.1 已含，值域：`vllm-cli` | `custom`）。
3. **投机解码块**（L114-124）：`spec.decode` 门禁（与步骤 1 的 die 检查双保险，此处防
   模板链中途覆盖）。
4. **观测 flag 块**（L126-201：steps L146-155 / deep L159-171 / kernel L173-201）：
   由步骤 2 的 `ENGINE_ARGS_MODE=vllm-cli` 门禁整体覆盖（这些全是 vLLM CLI flag），
   不再逐块 if。
5. **插件块**（L203-237）：`obs.step-log` 门禁（含 docker 侧 PLUGIN_SETUP L228-232）。
6. **EXTRA 追加**（L239-250）：`EXTRA_VLLM_ARGS` 追加逻辑保留，但前面加
   `ENGINE_ARGS_MODE=custom` 时的 ⚠️ 忽略告警；`EXTRA_ENGINE_ARGS` 在其后以相同切分逻辑
   追加（对 vLLM 两者先后拼接，`ENGINE=vllm` 未设置 `EXTRA_ENGINE_ARGS` 时结果与基线一致）。
7. **环境变量段**（L252-279）：vLLM 专属 env（L265-270）与 `VLLM_LOGGING_LEVEL` 等
   （L142-156 已在拼装段）按 `ENGINE_ARGS_MODE` 收拢；通用段（TOKENIZERS_PARALLELISM 除外
   ——它也是 vLLM 的，一并收拢；`PYTHONUNBUFFERED`/`EXTRA_ENV`/`PROMETHEUS_*` 保留通用）。
8. **入口段**（L281-289）：优先级 `HOST_SERVE_ENTRYPOINT` > `ENGINE_ENTRYPOINT` >
   现有默认（host 侧 `host_serve_entrypoint`，common.sh:391-397；docker 侧 L287 的
   硬编码 `from vllm.entrypoints.cli.main`）。docker 入口非 vLLM 已在步骤 1 die，
   这里只需把 L287 包一层 `ENGINE_ARGS_MODE=vllm-cli` 判断以保基线不变。
9. **就绪等待**（L560-584）：轮询 `/metrics` 匹配 `$VENDOR_READY_METRIC`
   （默认 `^vllm:cache_config_info`，common.sh:188）。新增 profile 字段
   `ENGINE_READY_METRIC`（正则）：非空则覆盖厂商默认（优先级 显式 `VENDOR_READY_METRIC`
   > `ENGINE_READY_METRIC` > 厂商默认）；无 `metrics.vllm-named`/`metrics.prometheus`
   能力的引擎退化为只等 `/health`（`wait_http`，common.sh:840-854）。

**验收**：`ENGINE` 未设置时三份基线 diff 为空；`ENGINE=vllm` 显式设置时同样为空。
