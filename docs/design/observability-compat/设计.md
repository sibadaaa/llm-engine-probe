# F3 · 观测面组件兼容 — 设计

> 状态：**待施工**（任务分解见同目录 [施工图.md](施工图.md)）。
> 前置：F1 完成（`probe/engines.py` 注册表、`ProbeConfig.engine`、hostcheck 引擎感知）。
> 本文约定探针层（`probe/*.py` 与 `scripts/status.sh`）如何**按引擎能力协商**，把

## 1. 问题边界（调研结论，锚点见施工图）

Python 侧的引擎耦合集中在四类符号（F1 已处理第五类——启动链与身份落产物）：

| 类别 | 位置 | F3 处理方式 |
|---|---|---|
| 指标名常量与 `vllm:` 前缀过滤 | `metrics_probe.py:324-333/369-447/458-465`、`cli.py:105-125/231`、`save_tsv`、`diff_snapshots` | 派生 `metric_prefix`（flavor 决定）+ 抓取后缀；名字常量**不改**（Strata 恰好说 vLLM 名） |
| 请求体/流式 delta 键假设 | `http_probe.py:160`（reasoning_effort 注入）、`:275-308`（delta 键）、`:401-453`（per-request schema） | profile 化：`chat_body_extras` / `delta_content_keys` / caps 门禁 |
| 归因与报告的 vLLM 专属文案 | `report.py:967-1281`（diagnose 全是 vLLM flag 建议）、`_section_*` 空白小节 | 引擎行 + 能力降级注记 + 建议文案按 profile 替换 |
| 日志/trace/插件格式假设 | `log_probe.py`（vLLM 日志正则）、`trace_probe.py:49-52`（注解正则）、插件生态 | 声明式：无解析器/无 profiler 能力 → 显式提示，不做静默空输出 |

**不做**（F3 非目标）：`telemetry.py`（SMI 层本就引擎无关）、`plugin_records.py`
（消费端引擎无关）、`vendors/` 与遥测后端、`suite.py` 的场景矩阵语义（只加 engine 字段）、
compare 的 schema（缺项 null 已兼容）。

## 2. `EngineProfile` 扩展字段（Python 侧专有，无 shell 对应物）

> 这些字段描述"探针如何打这个引擎"，shell 端（启动/清理）用不到，因此**不进**
> `engines/<id>.sh`，也不参与 `tests/test_engines.py` 的双端一致性（一致性守卫只覆盖
> F1 的 shell 字段）。在 `probe/engines.py` 模块注释里写明这个分层。

| 字段 | 类型 | vllm 取值（=现行为） | strata 取值 |
|---|---|---|---|
| `metric_prefix` | `str` | `"vllm:"` | `"vllm:"`（flavor=vllm-named 的派生默认；非 vllm-named 引擎可改） |
| `chat_body_extras` | `dict[str, Any]` | `{"chat_template_kwargs": {"reasoning_effort": "low"}}` | `{"reasoning_effort": "low"}`（顶层键，上游语义） |
| `delta_content_keys` | `tuple[str, ...]` | `("content", "reasoning_content", "reasoning")` | `("content", "reasoning_content")` |
| `env_check_metrics` | `tuple[str, ...]` | 现 `cli.py:105-125` 的 7 项 + `vllm:cache_config_info` | TTFT/ITL/e2e 直方图 + running/waiting + prefix_cache_hits |
| `extra_metric_families` | `tuple[str, ...]` | `()` | `("strata:live_", "strata:last_", "strata:totals_", "strata:gpu_", "strata:ram_", "strata:cpu", "strata:engine_")` |
| `diagnose_overrides` | `dict[str, float]` | `{}` | `{}`（模式同 `probe/vendors.py:44`，留扩展点） |

## 3. 各探针面的协商行为

### 3.1 metrics（`probe/metrics_probe.py`）

* **抓取**：URL = `cfg.metrics_url` + profile 的抓取后缀（F1 字段
  `metrics_fetch_suffix`，Strata 为 `?format=prometheus`）；flavor 非 `none` 时加请求头
  `Accept: text/plain`（vLLM 忽略该头，行为不变；产物里不落请求头，基线不受影响）。
* **解析/分位数/单位推断**：完全引擎无关，**不动**（`_SAMPLE_RE` :31-36、
  `parse_metrics_text` :202-245、`histogram_quantile_detail` :258-296、`histogram_unit` :468-481）。
* **名字过滤参数化**：3 处 `startswith("vllm:")`（`save_tsv` :188-194、`diff_snapshots` :503、
  `cli.py:231` 的 `--print`）改为 `startswith(profile.metric_prefix)`；对 vllm/strata
  结果不变。
* **缺项容错**：`stage_table` 的 `available=False` 行（:343-347）与 `engine_state` 的
  0/None 容错已够用，报告注记由 §3.3 补（"Strata 缺 X/Y 直方图属预期"）。
* **可选增强（T3.8）**：快照 JSON 增 `engine_extra` 段，按 `extra_metric_families` 前缀
  采集 `strata:*`（专家缓存命中率 `strata:last_hit_rate`、实时速率 `strata:live_tok_s`、
  硬件 `strata:gpu_*`/`strata:ram_*`）；TSV 追加列；报告 §4（调度/KV）读
  `strata:last_hit_rate` 补一行"专家缓存命中率（引擎侧）"。缺省关闭（`--engine-extras` 或
  配置开关），避免非 Strata 场景产物 schema 变化。

### 3.2 http（`probe/http_probe.py`）

* `_build_body`（:149-163）：`chat_template_kwargs` 注入改为 `profile.chat_body_extras`
  合并；`ENGINE=vllm` 时请求体与现状逐字节一致。
* `_absorb_chunk`（:275-308）：内容键序列取 `profile.delta_content_keys`；`fallback
  choice.text`、usage、`finish_reason` 等通用逻辑不动。
* per-request metrics 摘要（`_server_side_summary` :401-421、`_spec_decode_summary`
  :424-453）：仅当 profile 有 `obs.per-request-metrics` 才解析（否则现状的
  `available:False` + hint 即最终态，不再尝试）。
* `x-request-id` / `x-vllm-request-id`（:197）：保持现有兜底顺序，不 profile 化（通用头）。
* TTFT 语义（reasoning 计入首 token）保持——对思考型引擎（Strata）这是正确的口径，
  在报告注记里说明。

### 3.3 report（`probe/report.py`）

* **引擎行**：`_section_overview` 的 rows（:240-253）紧跟厂商行加「引擎」，取值链
  `run_meta.json 的 meta.engine`（F1 T1.9 写入）→ `ENGINE` 环境变量 → `"vllm"`；
  解析模式复用 `_artifact_vendor`（:170-175）/`_vendor_label`（:178-190）的现成结构。
* **能力降级注记**：小节头按 caps 生成一句话，替代空白：
  * §3 引擎 step 级（`_section_steps` :474）与 `_plugin_block`（:381-471，含 "vLLM=版本"
    文案 :387）：无 `obs.step-log` → "引擎 X 不支持逐 step 日志/插件观测，本节为空"；
  * §5 投机解码（:677）：无 `obs.per-request-metrics` 时在 per-request 段头注明
    "仅有 /metrics 级计数器（如引擎提供）"；
  * §7 算子/kernel（:795）：无 `obs.trace-pytorch` → "引擎 X 无 torch profiler 面板，
    kernel 归因不适用"；
  * §4 调度/队列/KV（:595）：vLLM 专属指标缺失行照旧显示 `available=False`，
    节头追加一句 profile `report_notes`。
* **diagnose 引擎化**（:967-1281）：诊断逻辑与阈值**不动**；仅当 `engine != vllm` 时，
  输出建议里的 vLLM CLI flag 文案（--max-num-seqs :1008、--max-model-len :1021、
  --enable-prefix-caching :1078、--enforce-eager :1257 等）替换为 profile `report_notes`
  的一句话（实现模式对齐现有 vendor 分支 :1155-1173/:1259-1262）；`thresholds_for`
  （:954-964）在 vendor 覆盖之后合并 `engine.diagnose_overrides`。
* 报告 TITLE（:151）与头部加引擎名（`REPORT.md` 标题行后追加 "引擎：X"）。

### 3.4 CLI 与套件（`probe/cli.py`、`probe/suite.py`）

* `add_common`（:39-47）加 `--engine`（默认 None → `ENGINE` 环境 → `vllm`），经
  `cfg_from` 进 `ProbeConfig.engine`；所有子命令统一携带。
* `cmd_env` 的可选指标存在性表（:105-125，含 `vllm:cache_config_info` :116）改为
  按 `profile.env_check_metrics` 生成；`env_check.json` 已含 vendor 字段（:172-176），
  同处加 `engine`。
* `cmd_metrics --print`（:231）前缀过滤见 §3.1。
* `cmd_trace`（:333）：纯文件分析，不做引擎门禁；文件头注释加一句"非 torch 引擎的
  trace 无法用本命令分析"。
* `cmd_hostcheck`（:630-644）：F1 已接 `ENGINE`，此处只确认透传。
* `suite.py`：`suite_results.json` 的 payload 增 `engine`（挂点 :266-291 的上下文区；
  `run_scenario` 的 metrics try 已容错 :146-149）；`kind` 字符串
  `"vllm-probe-suite"`（:328/:391-392）**保留**（schema 兼容层，改名会破坏 compare）。

### 3.5 status / 日志（shell 侧）

* `scripts/status.sh`：`/metrics` 探测（:81）与解析（`vllm:cache_config_info` :110）加
  F1 的 `ENGINE_METRICS_FETCH_SUFFIX`；版本探测已由 F1 T1.9 处理。
* `probe/log_probe.py`：不实现 Strata 日志解析；`probe logs` 在 engine 无解析器时
  （profile 声明，见 T3.9）打印一句提示后进入 `--raw` 透传模式，不报错。

## 4. 测试策略：mock 的引擎 flavor

`tests/mock_vllm_server.py` 加 `--flavor vllm|strata`（默认 vllm，现行为不变）：

| 行为 | vllm flavor（现状） | strata flavor |
|---|---|---|
| `/metrics` | 恒 Prometheus 文本 | 默认 JSON（`{"error":"use format=prometheus"}` 形状）；带 `?format=prometheus` 或 `Accept: text/plain` 才回文本 |
| 指标集合 | 现有 `vllm:*` 全集 | vLLM 名**子集**：running/waiting、kv_cache_usage_perc、prefix_cache、spec_decode 计数器、TTFT/ITL/e2e 直方图；**无** 5 个生命周期直方图、无 `cache_config_info`、无 kv_block_*；另加 `strata:live_tok_s`、`strata:last_hit_rate`、`strata:gpu_util` 样本 |
| chat delta | 现有（content + per-request metrics） | `reasoning_content` 前缀若干块 + content；**无** `chunk.metrics`；无 `x-vllm-request-id` |
| `/v1/completions` | 支持 | 404（OpenAI 端点缺失路径） |
| `/v1/models` | 现有 | `id: "strata"` |

`tests/run_tests.sh` 的 mock e2e（:61-171）在现有链路后追加"strata flavor 段"：
起第二个 mock（`--flavor strata`）→ `probe env/metrics/http/suite/report` 各断言：
engine 字段落产物、缺项行 `available=False`、suffix 抓取命中、report 降级注记出现、
vLLM 链路产物 diff 不变。**无硬件全链路回归**由此成立。

`tests/test_parsers.py` 补：strata 指标子集解析、JSON 默认响应的容错、
`delta_content_keys`（strata 集）的 TTFT 计算、`extra_metric_families` 采集。
